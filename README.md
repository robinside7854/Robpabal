# 구파발 출근길 🚇

서울 지하철 **3호선 구파발역**에서 출발하는 사람을 위한 출근 시간 계산기입니다.

> **"몇 시에 집에서 나가야 지각을 안 할까?"**
> 이 질문 하나에 답하는 것이 이 앱의 전부입니다.

자주 가는 도착역(회사·학교 등)을 즐겨찾기해두면, 목표 도착 시각에 맞춰
**집에서 나가야 할 시각**과 **남은 시간 카운트다운**을 보여줍니다.

---

## 무엇이 다른가요

| 기능 | 설명 |
|---|---|
| 🔖 도착역 즐겨찾기 | 회사·본사·학원처럼 여러 목적지를 등록하고 탭으로 전환합니다. 목적지마다 목표 도착 시각을 따로 정합니다. |
| 🚶 도보 시간 2단계 | `집 → 구파발역 승강장` 과 `도착역 → 사무실` 을 따로 입력해 실제 문 앞 기준으로 계산합니다. |
| 🔄 시간표 자동 갱신 | 서울시 공공데이터에서 최신 시간표를 매주 자동으로 받아옵니다. |
| 🟠 3호선 오렌지 | 3호선 노선색(#EF7C1C)을 기준으로 한 화면입니다. |

### 계산 방식

```
집에서 나갈 시각 = 열차 출발 시각 − (집→구파발 도보 + 여유 버퍼)
사무실 도착 시각 = 열차 출발 시각 + (구파발→도착역 소요 + 도착역→사무실 도보)
여유              = 목표 도착 시각 − 사무실 도착 시각
```

## 1. 바로 써보기

이 저장소는 그냥 웹페이지 묶음이라 **설치가 필요 없습니다.**

### 방법 A. 내 컴퓨터에서 열기

브라우저 보안 정책 때문에 `index.html` 파일을 더블클릭하면 시간표를 못 읽습니다.
터미널에서 아래 한 줄을 실행한 뒤, 주소창에 `http://localhost:8000` 을 입력하세요.

```bash
python3 -m http.server 8000
```

### 방법 B. 인터넷에 올려두고 폰에서 보기 (추천)

**먼저 저장소가 Pages를 쓸 수 있는 상태여야 합니다.**
GitHub Pages는 **공개(Public) 저장소**에서 무료입니다. 비공개 저장소는 GitHub Pro 이상이어야 합니다.
비공개 상태라면 `Settings` → 맨 아래 `Danger Zone` → `Change repository visibility` 에서 Public으로 바꿔주세요.

**그리고 Pages를 한 번 켜주셔야 합니다.**
`Settings` → 왼쪽 메뉴 `Pages` → `Source` 를 **GitHub Actions** 로 고릅니다.
이 클릭은 사람이 직접 해야 합니다. 워크플로가 대신 켜보려 시도는 하지만,
GitHub Actions 토큰에는 Pages 사이트를 새로 만들 권한이 없어서
`Create Pages site failed. Error: Resource not accessible by integration` 으로 막힙니다.

이 두 가지만 끝나면 나머지는 자동입니다.

1. `main` 브랜치에 코드가 올라가면 배포 워크플로가 실행됩니다.
2. 몇 분 뒤 `https://<내아이디>.github.io/<저장소이름>/` 에서 열립니다.
3. 폰 브라우저로 접속해 **홈 화면에 추가**하면 앱처럼 쓸 수 있습니다.

배포가 실패하면 `Actions` 탭에서 **GitHub Pages 배포** 워크플로의 로그를 확인하세요.
자주 나오는 두 가지는 이렇습니다.

| 로그에 뜨는 말 | 뜻 |
|---|---|
| `Get Pages site failed ... Not Found` | Pages를 아직 안 켰습니다 (위 `Settings` → `Pages`) |
| `Create Pages site failed ... Resource not accessible by integration` | 위와 같습니다. 워크플로가 대신 켜려다 권한이 없어 실패한 것입니다 |

Pages를 켠 뒤에는 `Actions` 탭 → **GitHub Pages 배포** → `Re-run all jobs` 로 다시 돌리면 됩니다.
(설정만 바꿔서는 배포가 다시 돌지 않습니다. 새 실행을 띄워야 합니다.)

**기본 브랜치가 `main`이 아니면 배포가 막힙니다.**
Pages를 켜면 GitHub이 `github-pages` 라는 배포 환경을 자동으로 만드는데,
여기에는 "저장소의 기본 브랜치에서만 배포 허용" 이라는 규칙이 기본으로 붙습니다.
배포 워크플로는 `main` 에서 도는데 기본 브랜치가 다른 이름이면 관문에서 거부됩니다.

이때는 실행이 **몇 초 만에 실패하고 로그가 아예 없습니다.** 스텝이 하나도 실행되지
않았기 때문입니다 (잡 상태가 `waiting` 으로 끝납니다). 로그가 없다고 당황하지 마시고
`Settings` → `General` → `Default branch` 가 `main` 인지 확인하세요.

기본 브랜치를 `main` 으로 맞추는 것은 어차피 필요합니다. 아래 **시간표 자동 업데이트**의
예약 실행(cron)도 기본 브랜치에서만 동작하기 때문입니다.

> 설정값(도보 시간·즐겨찾기)은 서버가 아니라 **내 브라우저 안에만** 저장됩니다.
> 다른 기기에서 열면 다시 설정해야 합니다.

## 2. 사용법

1. **＋ 도착역 추가** 를 누릅니다.
2. 네 가지를 채웁니다.
   - **이름** — 나중에 알아보기 쉬운 별명 (예: `회사`)
   - **도착역** — 3호선 역 목록에서 고릅니다. 괄호 안 숫자는 구파발에서 걸리는 시간입니다.
   - **도착역 → 사무실 도보** — 지하철에서 내려 사무실 문까지 걷는 시간
   - **목표 도착 시각** — 이 시각까지는 도착해야 하는 시간 (예: `09:00`)
3. 아래 **도보 · 여유 설정** 에서 `집 → 구파발역 승강장` 시간을 넣습니다.
   - 집을 나서서 **개찰구를 지나 승강장에 서기까지** 걸리는 시간으로 넣는 게 정확합니다.
   - **여유 버퍼** 는 신호 대기, 엘리베이터 기다림 같은 예비 시간입니다. 2~3분을 권합니다.

이제 주황색 큰 카드에 **집에서 나갈 시각**과 카운트다운이 나옵니다.

### 화면 읽는 법

- **초록 테두리** — 여유 있게 목표 시각에 도착합니다.
- **노란 테두리** — 서둘러야 하거나, 타더라도 목표 시각보다 늦습니다.
- **회색 + 취소선** — 지금 집에서 나가도 이미 탈 수 없는 열차입니다.
- **급행 표시** — 3호선 급행 열차입니다. (일산 방향에서는 도착이 더 빠릅니다)

> ⚠️ **공휴일은 자동으로 알아보지 못합니다.** 설날·추석 같은 날에는
> `도보 · 여유 설정` 의 **요일 기준** 을 `휴일·일요일` 로 직접 바꿔주세요.

## 3. 시간표 자동 업데이트 켜기

처음에는 손으로 넣은 **초기 시간표(평일·오금 방향)** 만 들어 있습니다.
아래를 한 번만 해두면 매주 월요일 새벽에 서울시 공공데이터에서
**평일·토요일·휴일 × 양방향 전체 시간표**를 자동으로 받아옵니다.

### ① 무료 인증키 받기 (5분)

1. [서울 열린데이터 광장](https://data.seoul.go.kr/) 에 접속해 회원가입합니다.
2. 상단 메뉴에서 **데이터셋 → Open API** 로 들어가
   `지하철역별 요일별 운행시간표` 를 검색합니다.
3. **인증키 신청** 을 누르고 사용 목적을 간단히 적으면 즉시 발급됩니다.
4. 발급된 긴 문자열(인증키)을 복사해둡니다.

### ② GitHub에 인증키 등록하기

1. 이 저장소 페이지에서 **Settings** 로 들어갑니다.
2. 왼쪽 메뉴 **Secrets and variables** → **Actions** 를 누릅니다.
3. **New repository secret** 버튼을 누릅니다.
4. 이름에는 정확히 `SEOUL_OPENAPI_KEY` 를 적고, 값에는 복사한 인증키를 붙여넣습니다.
5. **Add secret** 으로 저장합니다.

> 🔒 인증키는 GitHub가 가려서 보관하며, 코드나 로그에 그대로 찍히지 않습니다.

### ③ 한 번 직접 돌려보기

1. 저장소 상단의 **Actions** 탭을 누릅니다.
2. 왼쪽에서 **시간표 자동 업데이트** 를 고릅니다.
3. 오른쪽 **Run workflow** 버튼을 누릅니다.
4. 2~3분 뒤 초록 체크가 뜨면 성공입니다. 앱을 새로고침하면
   화면 맨 아래 문구가 `서울열린데이터광장` 으로 바뀝니다.

이후에는 **매주 월요일 새벽 4시(한국시간)** 에 알아서 갱신됩니다.

### 내 컴퓨터에서 돌리고 싶다면

```bash
SEOUL_OPENAPI_KEY=발급받은키 node scripts/update-timetable.mjs
```

## 4. 폴더 구조

```
index.html                         화면 구조
assets/app.css                     3호선 오렌지 테마
assets/app.js                      시간 계산과 화면 갱신
data/line3-gupabal.json            시간표 데이터 (자동 갱신 대상)
scripts/update-timetable.mjs       공공데이터에서 시간표를 받아오는 프로그램
scripts/seed-timetable.mjs         초기 시간표를 만드는 프로그램
.github/workflows/update-timetable.yml  매주 자동 갱신
.github/workflows/pages.yml             GitHub Pages 자동 배포
```

### 시간표 데이터가 생기는 과정

```
서울 열린데이터 광장 API
  │  ① 3호선 역 목록과 역코드를 받는다
  │  ② 구파발역의 요일별·방향별 출발 시간표를 받는다
  │  ③ 각 역의 시간표를 받아 '열차번호'가 같은 열차끼리 짝지어
  │     구파발 출발 → 그 역 도착까지 실제 몇 분 걸리는지 계산한다
  ▼
data/line3-gupabal.json  →  앱이 이 파일 하나만 읽습니다
```

③ 덕분에 역별 소요시간을 사람이 일일이 적을 필요가 없고,
급행과 일반 열차의 소요시간도 따로 계산됩니다.

**안전장치** — 받아온 데이터가 이상하면(역이 40개 미만이거나 열차가 30편 미만이면)
기존 파일을 덮어쓰지 않고 실패로 끝납니다. 잘못된 시간표가 올라가는 것을 막기 위해서입니다.

## 5. 자주 묻는 것

**Q. 소요시간 옆 "(추정)"은 뭔가요?**
아직 자동 업데이트를 한 번도 안 돌렸다는 뜻입니다. 초기 데이터는 역당 약 2분으로
계산한 어림값이라 실제와 1~3분 차이가 날 수 있습니다. 위 3번을 따라 하면 실측값으로 바뀝니다.

**Q. 토요일에 열었더니 "시간표가 비어 있습니다" 라고 나옵니다.**
초기 데이터에는 평일 오금 방향만 들어 있어서 그렇습니다. 자동 업데이트를 켜면 채워집니다.

**Q. 실시간 지연 정보도 나오나요?**
아니요. 이 앱은 **계획된 시간표** 기준입니다. 실제 운행은 상황에 따라 달라질 수 있습니다.

**Q. 다른 역에서 출발하도록 바꿀 수 있나요?**
`scripts/update-timetable.mjs` 맨 위의 `ORIGIN_NAME` 을 다른 3호선 역 이름으로 바꾸고
업데이트를 돌리면 됩니다.
